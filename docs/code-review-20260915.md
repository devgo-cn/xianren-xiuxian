## 一、性能问题

### 1. 战斗系统弹窗打开时不暂停（中优先级）
- **位置**：`index.html` 战斗系统 `update()` 函数
- **问题**：打开离线收益、云存档、云游、丹房等弹窗时，战斗系统继续运行 `requestAnimationFrame` 循环，怪物继续生成、攻击、移动
- **影响**：玩家看弹窗时战斗在后台继续进行，可能错过战斗画面；额外消耗 CPU
- **守卫现状**：仅 `enterDim/exitDim` 时调用 `BattleAPI.pause/resume`，其他弹窗无处理
- **修复方向**：检测 `.modal.show` 元素存在时暂停战斗，或在各弹窗 open/close 时调用 BattleAPI.pause/resume

### 2. 战斗系统无 visibilitychange 监听（低优先级）
- **位置**：`index.html` 战斗系统
- **问题**：切到后台标签页时，`requestAnimationFrame` 通常被浏览器暂停，但恢复时 `lastT` 未重置，可能导致大 `dt` 跳帧
- **现有保护**：`dt = Math.min(0.05, ...)` 限制了最大帧间隔，部分缓解
- **修复方向**：加 `visibilitychange` 监听，恢复时重置 `lastT = performance.now()`

### 3. 战斗系统每帧全量重绘（低优先级）
- **位置**：`render()` 函数
- **问题**：每帧 `clearRect` + 重绘背景/云层/地板/所有怪物/玩家/特效，无分层缓存
- **影响**：当前战斗单位少（1玩家+少量怪物），性能影响可忽略；后续多宠物上线时需关注

## 三、错代码

### 1. 玩家与怪物渲染 x 偏移不一致（低优先级）
- **位置**：`index.html:1097` 玩家用 `-drawW*0.35`，怪物用 `-drawW*0.5`
- **问题**：玩家锚点偏左 35%，怪物居中 50%，导致玩家和怪物的 x 坐标参考点不同
- **影响**：攻击距离判定 `Math.abs(e.x - p.x)` 可能有轻微偏差（约 15% 角色宽度）
- **修复方向**：统一锚点，或在攻击距离判定中补偿偏移差

### 2. 已修复：topStack 闭合标签缺失
- **原因**：commit `6a55ce1` 删 `hunt-bar/war-banner` 时多删了一个 `</div>`
- **影响**：`top-stack` 吞掉后续 26 个元素，导致行迹区域点击穿透
- **状态**：已由另一个 Agent 修复

## 六、其他发现

### 1. 调试句柄暴露（低风险）
- `window.__game` 暴露 state/srvOffset/rate/pred 等，便于调试但也便于作弊
- **建议**：生产环境可考虑移除或加混淆

### 2. console 残留（可接受）
- 仅 4 处 `console.error/warn`，均在 fx2d/WebGL 初始化失败时，合理

### 3. innerHTML 使用（需关注）
- game.js 大量使用 innerHTML 动态生成内容，用户输入（玩家码、存档名）有 `esc()` 转义，XSS 风险可控
