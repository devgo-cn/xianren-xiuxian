## 〇、设计立场

| 立场 | 说明 |
|---|---|
| 战斗区是**表演** | 敌我血量刻意设成"一刀秒/几刀秒"，追求节奏感而非数值深度 |
| 玩家不会真死 | `if (p.hp <= 0) p.hp = p.maxHp;`（满血复活）——不能让背景装饰打断主游戏 |
| 判定用**一维水平距离** | 本系统无纵向机动，不做像素包围盒碰撞 |
| 服务权威、客户端表现 | 客户端渲染与预测，结算由服务端负责 |
| 规范描述现状，不预设美术 | 素材怎么画、画多大，**不由本文档规定** |

## 一、系统边界

| 职责 | 归属 |
|---|---|
| 玩家推进、刷怪、攻击、受击、死亡消散 | 战斗系统（`index.html` 内战斗 IIFE） |

## 二、坐标系与几何规范

### 2.1 坐标定义

| 概念 | 定义 | 说明 |
|---|---|---|
| **世界坐标 `x`** | 角色在世界中的横坐标，只增不减 | 玩家持续向 `+x` 推进 |
| **摄像机 `camX`** | 视口左边缘对应的世界坐标 | `camX = player.x - stageW()*0.28` |
| **屏幕坐标 `sx`** | `sx = worldToScreen(x) = x - camX` | 唯一渲染入口 |
| **地面线 `floorY()`** | `CH * 0.82` | 所有角色的**脚底**落在此线上 |
| **垂直坐标 `y`** | 相对地面的偏移（`translate(sx, floorY())`） | **不要**用绝对 Y 定位角色 |

**铁律**：角色逻辑坐标只用**世界 X**；一切绘制必须经 `worldToScreen()`。

### 2.2 摄像机

```js
const targetCam = G.player.x - stageW()*0.28;      // 主角恒定在视口 28% 处
G.camX += (targetCam - G.camX) * Math.min(1, dt*6); // 阻尼跟随，不硬切
```

| 参数 | 值 | 含义 |
|---|---|---|
| 主角屏幕锚点 | `28%` | 主角永远显示在视口左侧 28% |
| 跟随阻尼 | `dt*6` | 掉帧时不"跳跃追帧"，对移动端低帧率至关重要 |

### 2.3 攻击范围（`atkRange`）

攻击范围是**世界坐标下的水平距离**，判定与移动都用它。

| 实体 | `atkRange` | 语义 |
|---|---|---|
| 玩家 | `75` | 剑锋可及的左右各 75 世界单位 |
| 妖卒 slime（近战） | `30` | 贴身才打得到 |
| 水灵 water（近战） | `35` | 略长，血厚（hp 2） |
| 妖将 demon（近战） | `35` | 略长 |
| 妖弓 raptor（远程） | `110` | 远程压制 |
| 宠物（默认） | `50` | `addPet` 可覆盖 |

**判定公式**：

```js
// ① 玩家起手：距离 ≤ atkRange + 5
if (near && Math.abs(near.x - p.x) <= p.atkRange + 5) { /* 起手 */ }

// ② 敌人停步：停在玩家 atkRange 处（+2 死区防抖）
const stopX = p.x + e.atkRange;
if (e.x > stopX + 2) e.x = Math.max(stopX, e.x - e.speed*dt);

// ③ 玩家命中：距离 ≤ atkRange + 15（比"起手"宽 10，防走位抖动导致空刀）
if (Math.abs(p.attackTarget.x - p.x) <= p.atkRange + 15) { /* 结算 */ }

// ④ 索敌：视野远大于攻击范围
findNearestEnemy(p.x, p.atkRange + 200);
```

| 容差 | 值 | 作用 |
|---|---|---|
| 起手 `+5` | 5 | 略宽于 atkRange，避免边界抖动反复切状态 |
| 命中 `+15` | 15 | 起手到出招有动画延迟（帧 10 / 帧 26），角色可能已轻微错位 |
| 索敌 `+200` | 200 | 保证"看得见"屏幕边缘刚刷出的怪（宠物为 `+100`） |
| 停步 `+2` | 2 | 防止 `e.x == stopX` 处抖动 |

> `atkRange` 与 sprite 尺寸**完全解耦**：换素材、改画布高度都不会改变判定距离。
> 反过来，美术把武器画长了 30%，`atkRange` 就该同比调——否则刀尖碰到敌人却不掉血（§7.1）。

### 2.4 移动与推进

- 玩家**自动向 `+x` 推进**，速度 `BC.playerSpeed = 28`；攻击动画期间 `p.moving = 0`（站定出招）
- 敌人从屏幕右外侧 `G.camX + stageW() + 40` 生成，向 `-x` 走来
- 到达 `p.x + e.atkRange` 停步并攻击

## 三、时间与节拍

### 3.1 帧循环

```js
const dt = Math.min(0.05, realDt);   // dt 上限 0.05s：切后台回来不会"瞬移"
const sdt = dt * G.speedMult;        // 逻辑用 sdt；动画/特效用 dt
```

> **逻辑用 `sdt`，表现用 `dt`**：倍速只加快战斗节奏，不把动画也快进成鬼畜。

### 3.2 倍速

| 技能 | 倍率 | 时长 | 触发概率 |
|---|---|---|---|
| `double` | 2x | 5s | 8% |
| `triple` | 3x | 3s | 3% |

接口已备（`trySpeedSkill` / `triggerSpeedSkill`），**由玩法层调用**，战斗层不自行 roll。

### 3.3 动画帧推进

- 动画 `24 fps`，`frameDur = 1/24`
- 走路用**时间驱动**（`Math.floor(t * fps) % count`），不用帧计数器——避免暂停/倍速后错位
- 攻击用**帧计数器** `animFrame`（必须精确落在判定帧上）

### 3.4 生成节拍

```js
G.spawnT -= sdt; if (G.spawnT <= 0) { spawnWave(); G.spawnT = BC.spawnInterval; }  // 1.4s
```

## 四、伤害与判定

### 4.1 玩家攻击：双段分帧判定

一次挥剑动画（40 帧）触发**两次**独立判定：

| 段 | 触发帧 | 攻击系数 | 暴击率 | 暴击倍率 | 伤害色 |
|---|---|---|---|---|---|
| 第一段（主刺） | `10` | `0.9~1.1` | `8%` | `1.8x` | `#7fe0ff` |
| 第二段（补刺） | `26` | `0.95~1.2` | `10%` | `2.0x` | `#a0e8ff` |

```js
dmg = p.atk * (base + random()*var) * (crit ? critMult : 1)
```

**死亡中断**：第一段把目标打死了 → 立即中断，不刺第二下（网游判定，目标已死不补刀）。
攻击动画播放期间**不可被新目标打断**。

### 4.2 攻击间隔

```js
p.atkT = 1 / p.aspd;   // 冷却 = 1/攻速
```

| 实体 | `aspd` | 间隔 |
|---|---|---|
| 玩家 | `1.1` | ~0.91s |
| 宠物（默认） | `1.0` | 1.0s |
| 敌人 | `0.8 + random*0.5` | 0.8~1.3 次/秒（**随机化，避免齐攻**） |

### 4.3 敌人攻击

**现状：起手即结算**（无分帧出手动画判定）。

```js
if (Math.abs(e.x - p.x) <= e.atkRange + 5 && e.atkT <= 0) {
  e.anim = 1; e.atkT = 1/(0.8 + Math.random()*0.5);
  p.hp -= e.atk * (0.85 + Math.random()*0.3);   // 敌人伤害 ±15% 浮动
  p.hurtT = 0.25; p.stun = 0.5;
  if (p.hp <= 0) p.hp = p.maxHp;                 // 玩家不死
}
```

| 点 | 现状 |
|---|---|
| 冷却 | `atkT` 独立计时；`anim` 仅控制攻击动画显示（1 → 0，速率 `dt*1.5`） |
| 攻击中可移动 | 是（与玩家相反），保证"边追边打"的压迫感 |
| 受击反馈 | `hurtT = 0.25`s 白闪 + 亮度提升；`stun = 0.5`s 玩家僵直 |

### 4.4 索敌

```js
function findNearestEnemy(fromX, maxDist) { /* 跳过死亡/正在死亡的敌人 */ }
```

- 只看**水平距离**，不看垂直
- **死怪不可选中**：`if (!e.alive || e.dying > 0) continue;`
- `dying` = 已 `alive=false` 但仍在场上播消散（0.4s 淡出），此间不可被选中
- 索敌半径 `atkRange + 200`——**视野 > 攻击范围**，够不着时先走过去

## 七、血泪教训

### 7.1 攻击距离与视觉不符

**症状**：刀尖明明碰到敌人却不掉血，或隔空打牛。
**根因**：`atkRange` 是世界单位，与 sprite 尺寸无关；美术改了武器长度却没同步数值。
**教训**：改素材的视觉尺寸后，回头对一次 `atkRange`。

### 7.2 弹窗点不动（z-index 血案）

**症状**：弹窗打开后所有交互失效。
**根因**：战斗层 `.battle-stage` 的 `z-index` 高于 UI 层，铺满全屏的透明层吃掉了点击。
**规则**：`.battle-stage` 必须保持 `z-index: 1`，**低于 UI 最低层 5**。

### 7.3 角色抽搐/横跳

**症状**：走路时角色左右/上下抖动。
**根因**：每帧按独立 bbox 裁剪，框随姿态变 → 落点抖动。
**教训**：**不要按逐帧内容框决定缩放**。缩放应该整帧等比、固定不变；
逐帧内容框只适合用来做对齐参考，一旦拿来算 `k = hitH / box.h`，
蜷缩帧就会被拉高，表现为"拉伸得不成样子"（2026-09-15 实测，已回退）。

### 7.4 走路循环不流畅

**症状**：循环接缝处"顿一下"。
**根因**：首尾帧不是同一姿态。
**教训**：walk 段首尾必须能接上；`monster_002` 用的是"拉伸帧 + 倒放帧"拼出的回环，属于合法做法。

### 7.5 `NaN` 帧号

**症状**：角色**随机几帧消失**。
**根因**：`Math.floor(NaN) % n` 仍是 `NaN`，`drawImage` **静默失败**（不报错、不画）。
**教训**：帧号进 `drawImage` 前用 `Number.isFinite` 兜底。

## 八、代码规范

### 8.1 结构

战斗系统整体是 `index.html` 内的一个 IIFE，内部分层：

```
常量 BC → 状态 G → update*（逻辑）→ draw*（渲染）→ 对外 BattleAPI
```

### 8.2 命名约定

| 前缀 | 含义 |
|---|---|
| `BC.*` | 平衡与配置常量 |
| `G.*` | 运行时状态 |
| `update*` | 逻辑推进（受 `sdt` 影响） |
| `draw*` | 渲染（不得修改状态） |

### 8.3 数值调整纪律

- 平衡数值集中放 `BC`，避免在逻辑里散落
- 改判定手感时，先确认改的是"起手容差"还是"命中容差"（§2.3）

### 8.4 渲染规范

- `draw*` 函数**只读状态**，不做逻辑推进
- 所有角色绘制都以 `floorY()` 为脚底基准
- 变换（`translate` / `scale`）必须成对 `save()` / `restore()`
