# 旧系统拆除方案（v6 收尾）

> 目标：用户要求「旧的东西都删干净」——法宝、丹房、妖潮、云游四个系统，
> 外加旧境界/打坐体系，让 **05-v6 / 06-v6ui 成为唯一驱动源**。

## 一、现状：为什么「还能玩但很脏」

两套系统**并行在跑**，各自独立：

| | 旧系统 | v6 |
|---|---|---|
| 驱动 | `40-app.js` 的 `main()` rAF 循环 | `06-v6ui.js` 的 `setInterval(200ms)` |
| 修为 | `rateNow()` 打坐产出 → `state.exp` | 推关 → `05-v6.js` 的 `stage` |
| 境界 | `REALM_DAYS` / `SEG_META` / `realmIdx` | `00-realm.js` 的 54 层表 |
| 装备 | 法宝 `arts` + 词条 + 品质评分 | `00-equip.js` 的 4 格等级 |
| 存档 | `state` → `localStorage` | `saveV6()` **无调用方** |

玩家看到的是 v6 的界面（底部 4 按钮 + 关卡条），但底层旧循环仍在跑，
旧入口（法宝/丹房/妖潮/云游）也都还挂着。

## 二、拆除顺序（从外到内，每步都要能跑）

依赖方向：`index.html` → `40-app` → `30-systems` → `20-core` → `10-base` → `00-pure`
战斗层 `50-battle` 挂在 `10-base` / `20-core` 上。

### 阶段 1：接上 v6 存档（前置条件，先做）

**为什么先做这个**：删旧系统时会清掉 `state` 的大量字段，
而 v6 状态目前**根本没进存档**。不先接存档链路，删完就是「刷新即丢」。

- 把 `saveV6()` 接进 `20-core.js` 的 `save()`
- 把 `loadV6()` 接进 `load()` / `adopt()` 之后
- 存 4 样：离线（`runT`/`lastTick`）、境界（`realm`/`totalPoints`）、灵石（`spirit`）、装备（`equip`）

### 阶段 2：删云游 + 丹房（用户点名）

**云游**（travel）
- `00-pure.js`：`TRAVEL_*` 常量、`travel` / `mails` 状态字段
- `10-base.js`：`travelBtnLbl` / `travelMailCount` / `travelNextMailIn` / `travelSent` / `travelSecForMails`
- `20-core.js`：`showTravelMail` / `openTravel` / `_travelReturned`
- `30-systems.js`：云游相关全套
- `index.html`：`#travelModal`、`#mailModal`（化身手札）
- ⚠️ 云游挂着**离线叙事**，删掉会少一块氛围内容 —— 用户已确认

**丹房/丹方**（alchemy）
- `00-pure.js`：`RECIPES` / `MATS` / `cauldron` / `DAN_ZONE` / `MYST`
- `10-base.js`：`cauldron` / `selRecipe` / `fitsRecipe`
- `20-core.js`：`renderCraftBtn`
- `30-systems.js`：`openAlchemy` / `renderCraftBtn` / `recipeCan` / `recipeCardHTML`
- `index.html`：`#alchemyModal`、`#alchemyChip` 入口

### 阶段 3：删法宝（用户点名）

- `00-pure.js`：`ART_PREFIX` / `ART_SPECIAL` / `ART_SUFFIX` / `ART_*` 全表、`QUALITY`、`QW_TABLE`、`FX_POOL` / `FX_TXT`
- `10-base.js`：`makeArt` / `rollArt` / `artName` / `artMult` / `eqMult`
- `20-core.js`：`arts` / `artScore` / `_eqSel` / `licSync` / `renderBag` / `renderCabinet` / `smartEquip` / `_eqRecycle`
- `30-systems.js`：`renderFurn` / `attrAssign` / `pickNoRepeat`
- `40-app.js`：`updateArts` / `bindBattleHooks` 里的法宝部分
- `index.html`：`#equipModal`、`#equipChip`、`#furnModal`
- ⚠️ **保留** `dt-theme.css` 里 `.sk-*`（技能）与 v6 面板样式

### 阶段 4：删妖潮（用户点名，最复杂）

`50-battle.js` 里 **84 处**引用。妖潮不只是计时器——它**决定了刷怪逻辑**：
`trialSpawned` 控制刷第几批怪、什么时候出 BOSS、什么时候结算。

- 删 `BC.trialSecs` / `BC.trialPool` / `G.trial*` / `trialRestart` / `settleTrial`
- 重写刷怪循环：改为**无限刷怪**，玩家推关决定怪强度（这是 v6 的目标形态）
- 删 `#trialToast` / `#battleTrial`
- 删 `00-pure.js` 的 `trialBest` / `trialBoost` / `trialBoostUntil` / `BIGS[].segs`

### 阶段 5：删旧境界/打坐，v6 成为唯一驱动（用户点名）

- `40-app.js`：删 `loop(dt)` 里的 `rateNow()` 修为结算、`main()` rAF 循环、
  `adventure()` / `mainMoment()` / `checkMilestones()` / `realmPlot()`
- `30-systems.js`：重写 `updateHUD()`——只留 v6 需要的（`#spirit` / `#rateText`），
  删掉 legacy 分支（上一轮我留的 `if (legacy)` 守卫）
- `00-pure.js`：删 `REALM_DAYS` / `SEG_META` / `SEG4` / `SEG_SCALE` / `RK_NAMES` / `RK_SEGS` /
  `PAGES_NEED` / `ARRAY_COST` / `ARRAY_MAX_LV` / `PLOT` / `STORY_*` / `MOB_POOLS`
- `10-base.js`：删 `seg` / `段名` / `bigIndexOf` / `realm` 旧实现
- **验证 v6 驱动器仍活着**：`initV6()` 已调 `startDriver()`，删旧循环不影响 ✅

### 阶段 6：清 `state` 死字段 + 收尾

- `state` 只留 v6 要用的字段（如果 v6 状态仍寄存在 `state` 里）
- `40-app.js` 的 `main()` 循环若完全无人使用则删；`60-stage` 保留（战斗渲染仍要）

## 三、每阶段验收

1. `node tests/run-all.mjs` 329 断言全过
2. 浏览器实测：`hasStage` / `hasBattle` = true，kills 递增，无 console 错误
3. 存档往返：写入 → 刷新 → 状态保留
4. 截图确认界面无残留入口

## 四、风险

- **`50-battle.js` 是 4175 行的工具生成文件**，重写刷怪循环风险最高。
  文件头写着「本文件由工具生成，手改会在下次重建时丢失」——
  但 `tools/extract_battle.js` 已不存在，所以手改是目前唯一路径。
- 旧系统删干净后**不可回退到并行状态**，但 `main` 分支已有合并前的完整历史，
  出问题可 `git revert`。
